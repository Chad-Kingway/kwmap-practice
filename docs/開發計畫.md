# 第一階段：驗證 SDK 的動畫控制能力
1. 查閱勤崴 mapThree 文件，必要時補充參考相容版本的底層文件。
2. 確認 followPath() 的回傳值，以及是否提供正在播放的動畫控制物件。
3. 確認是否能在播放途中調整速度，並驗證實際效果。
4. 確認是否支援停止、暫停、續播，以及各自對回呼的影響。
5. 確認能否取得目前位置、播放進度及剩餘路徑。
6. 使用被 Git 忽略的測試檔案，驗證途中改速是否造成跳位、方向突變或重複動畫。
7. 檢查改速對鏡頭跟隨、onStart、onEnd 的影響。
8. 整理驗證結果，選擇直接調速、停止後續播，或自行管理動畫的方案。
# 第二階段：實作單車途中改速
1. 依驗證結果建立動畫控制介面，集中處理開始、改速與結束。
2. 開放接送期間操作全域速度滑桿，讓正在移動的車立即套用新倍率。
3. 保留官方預估時間作為基準，避免多次改速造成時間換算累積誤差。
4. 保持當下位置與路線進度連續，不回到起點、不跳過剩餘道路。
5. 保持車頭朝向與鏡頭跟隨穩定，不因每次改速重新定位鏡頭。
6. 確保接人、送人銜接時使用最新倍率，並維持正確的需求狀態。
7. 防止快速連續調速造成動畫重疊、過期回呼或需求重複完成。
8. 處理改速失敗與頁面清理，避免留下仍在執行的舊動畫。
9. 測試加速、減速、連續拖動、接近終點及路段切換等情境。
# 第三階段：整理全車共用時間控制
1. 集中保存全域速度倍率，讓各車輛共用同一份設定。
2. 若採自行管理動畫，建立共用模擬時鐘；若 SDK 支援直接調速，集中管理各車的動畫控制物件。
3. 每台車分別保存自己的路線、進度與任務狀態，避免互相覆蓋。
4. 全域改速同步影響所有運行中的車輛，新出發的車也套用當下倍率。
5. 定義背景分頁與回到前景時的時間處理，避免車輛突然大幅跳位。
6. 將動畫時間控制與接送狀態管理分開，方便後續增加車輛。
7. 建立車輛登記與移除流程，確保事件、動畫與資源能正確清理。
8. 以少量多車情境驗證共同改速、不同時間出發，以及各自完成任務。
9. 更新測試與開發計畫，記錄採用方案及仍存在的 SDK 限制。
